## 分析对象

- 文件：`ZOWIE v2524_DW_FW_Update_Tool.exe`
- SHA-256：`82c9288a39b6cdfedb3095ef24f8df00c2924a5c411a8eea808d03bc28886c82`
- 原生 x64 Qt 程序，包含 HIDAPI、Nordic 更新工具和多种鼠标固件。
- 仅静态读取更新器和固件文件，没有启动升级流程。
- 提取的接收器固件：`util/fw/XXDW/Benq_xxdw_dongle_v8511_update.zip`。
- 提取的鼠标固件：`util/fw/U2DW/Benq_udw_mouse_v2526_update.zip`。实机查询接收器缓存的鼠标版本为 `2526`，与分析文件的版本号一致；没有读取鼠标闪存作逐字节比对。

## 已在实机上验证

设备 `04A5:800A`，基站无线模式。通过 HID `FF03` 集合写入一个 16 字节 Output Report，然后从 `FF04` 集合用 ReadFile 等待 16 字节 Input Report。

| 用途 | 请求（补零至 16 字节） | 实际回复 | 解读 |
|---|---|---|---|
| 接收器固件版本 | `08 B4 40` | `09 85 11 00 C8 00 00 00 00 00 00 00 00 00 00 00` | 版本 `8511` |
| 缓存的鼠标电压 | `08 B4 15` | `09 01 82 00 C8 00 00 00 00 00 00 00 00 00 00 00` | 大端整数 `0x0182 = 386`；按固件计算链推断约 `3.86 V` |
| 缓存的鼠标固件版本 | `08 B4 25` | `09 25 26 C8 00 00 00 00 00 00 00 00 00 00 00 00` | 版本 `2526`；成功标记位于偏移 3 |

Report ID `08` 是输出，`09` 是输入。`C8` 在接收器版本和电压回复的偏移 4 处表示成功标记，在鼠标版本回复中位于偏移 3；它不是电量百分比。这里偏移均从报告 ID 起算，起始索引为 0。

该通信方式与 `HidD_GetInputReport` 不同：后者在此设备上返回 STALL；需要先发送已确认的查询，然后等待中断输入回复。

**已取得电池相关原始数据；尚未取得厂商提供的剩余容量百分比。不要把 386、86、C8 或电压线性映射成真实电量百分比。**

后续已追踪到电量灯的 ADC 阈值，并以离线执行原始固件核对了分档及换算。结合用户确认满电、取下后的约 4.14V 参考，已实现并实机运行明确标为估算的分段曲线；全程容量准确度验证尚未完成。详见 [百分比判断方法](BATTERY_PERCENTAGE.md)。

## 静态证据：更新器

地址为 PE RVA（加载基址 `0x140000000`）。本工具的分析输出只是反汇编，函数名及语义有些来自调用关系推断。

- `0x233E20` 枚举并打开 Usage Page `FF04` 和 `FF03` 两个 HID 集合。
- `0x22DA70` 构造版本查询；`0x6DE1E2C` 保存 `08 B4 40`。
- `0x2340A0` 先调用 HID 写入，再读取另一集合的回复。程序使用 64 字节临时缓冲区；本机 HID 能力信息给出的实际报告长度为 16，实测写入/读取 16 字节成功。
- `0x22BC90` 检查回复偏移 4 是否为 `C8`，以偏移 1、2 的大端值解析版本号。
- 已另外识别更新流程命令和会修改设置的其他固件处理分支；诊断脚本的白名单只包含上表三个读取命令。

## 静态证据：接收器固件 8511

以下地址是提取的 ARM Thumb 固件的文件偏移/代码地址。

- `0x1F4C`：命令分发，检查 Report ID `08`，将回复 ID 设置为 `09`。对大于等于 `0x15` 的命令要求前缀 `B4`。
- `0x2090`：`0x40` 命令分支，调用 `0x0CCE`，直接填入版本字节 `85 11`、`00`、`C8`。
- `0x209A`：`0x15` 命令分支，调用 `0x0CE0`。
- `0x0CE0`：调用 `0x4294`，将其 16 位返回值按大端写入回复偏移 1、2，偏移 3 填零，偏移 4 填 `C8`。此分支仅复制状态，无配置写入或更新动作。
- `0x4294`：从 RAM `0x2000002C + 0x1E` 读取 16 位缓存。
- `0x1232`：收到相应无线数据时，将其偏移 1 的字节加 `300`，保存到该缓存。
- `0x2036`：`0x25` 命令分支调用 `0x0D10`，后者通过 `0x42A8` 读取 RAM `0x2000002C + 0x1A` 的鼠标版本缓存，以大端返回，成功标记在偏移 3。此分支只读缓存。
- `0x5BBE` 附近收到 `0x40` 类型无线包后更新鼠标版本缓存。`0x7BEE`、`0x7C02` 的部分状态分支会将版本缓存清零；下述关机实测观察到了清零及开机恢复，睡眠等其他状态尚未验证。

## 静态证据：鼠标固件 2526

- `0x52DA` 附近的无线发送分支调用 `0x2908`，把返回值放入无线数据的偏移 1，与接收器 `0x1232` 的读取对应。
- `0x2908` 读取电池状态结构 `0x200000A8 + 0x20`，除以 `10`，再减 `300` 后编码成字节；含边界限制及特定值修正，不能当作未经处理的精密电压测量。
- `0x175C` 从采样值计算该状态量，正数路径为 `sample × 0x3CA50 / 0x38000`，并存入上述结构。结合数值范围与发送比例，查询值单位推断为 `0.01 V`。
- 鼠标有线端也包含 `0x15` 查询处理函数 `0x111E`，并额外填入状态字节；接收器同位置硬编码为零，因此基站回复中的零**不能据此解释为未充电**。

## 电压上报的刷新条件

- 鼠标 `0xD6F4` 的服务函数受模式及运行状态限制；部分状态会提前返回。
- 在状态值 3 或 5 的路径上，RAM `0x200000FC + 0x14` 的计数器累计到 500 后，`0xD780` 设置 `0x200000FC + 9` 的待发送标志并重置计数器。
- `0x5236` 的无线组包路径检查该标志；对应 `0x52DA` 分支构造 `0x20` 类型的电压包。还存在其他更优先的组包分支。
- `0x46E4` 通过另一个事件标志触发上述服务函数；目前没有确认这些服务计数对应的实际时间，**500 次计数不能直接换算成 500 毫秒或固定的刷新间隔**。
- 电脑端 `08 B4 15` 只取接收器缓存，增加查询频率不会强制鼠标采样或上报。

## 5 分钟充电对照（2026-09-25）

`voltage-refresh-5min.json` 记录了连续 300 秒的 150 次成功查询，值全部为 `388`，即按上述推断约 `3.88 V`。它与此前的 `386` 不同，说明跨记录的返回值确实发生过变化，但不能据此确定变化的原因及发生时刻。

用户在本轮记录期间确认完成了“充电约 2 分钟，再取下移动约 30 秒”；确认事件保存在 `voltage-refresh-5min-events.json`，距开始约 194 秒。充电、取下的精确时刻没有单独记录。整轮未观察到数值变化，因此这轮尚不能验证实时刷新或充电状态。

本轮结束后，`mouse-version-query-result.json` 保存的鼠标版本查询为 `2526`。

随后进行了 120 秒的串行电压、鼠标版本联合记录，见 `power-cycle-comparison.json`。记录期间电压始终为 `388`、鼠标版本始终为 `2526`，所有查询成功。用户后来明确表示该轮没有关闭鼠标，见 `power-cycle-comparison-events.json`，因此它只是保持开机状态的记录。

## 关机、重新开机对照（2026-09-25）

重新开始记录后，提示用户保持基站连接，关闭鼠标 20 秒，再开机移动、点击。用户在记录开始后约 114 秒确认完成，见 `power-cycle-retry-events.json`。串行查询原始报告保存在 `power-cycle-retry.json`。

| 距记录开始的时间 | 电压原始值 | 鼠标版本缓存 | 观察 |
|---|---|---|---|
| 0 秒 | 388 | `2526` | 操作前 |
| 56.90 秒 | 388 | `0000` | 版本清零，仍返回旧电压 |
| 77.22 秒 | 387 | `2526` | 版本恢复，电压缓存更新 |

上述时间是采样时间，不是物理开关的精确操作时刻，也不是断连检测延迟。版本为零的采样区间约 20 秒，与本次用户操作相符。

这轮确认了电压缓存会在重新连接后变化，并且鼠标关机期间接收器仍会成功返回旧电压。版本缓存清零可作为当前硬件、固件上的“未连接或状态未知”信号；恢复为 `2526` 表示接收器重新取得了鼠标版本信息。尚不能保证版本非零时的电压一定新鲜，也未验证睡眠、唤醒或所有充电状态。

## 限制及接入建议

此前 120 秒充电记录中，60 次读取均成功，原始值全部为 386。用户随后确认完成了充电约 30 秒、取下移动的操作，具体操作时间没有单独记录。收到确认后再次查询仍为 386，记录于 `voltage-after-confirmation.json`。该轮没有观察到缓存变化；本次关机对照才在同一记录中捕获了变化，仍不能推导正常使用时的固定刷新周期。

1. 查询得到的是接收器缓存；成功读到报告不证明鼠标此刻在线，也不证明缓存刚刚更新。鼠标版本为 `0000` 时，托盘应显示“未连接或状态未知”，隐藏当前电压或明确标为历史值；版本非零时也应把电压标为最近接收值，避免把查询时间当作采样时间。
2. 充电时的缓存更新行为和电压变化需要实测。时间序列保存于 `voltage-charge-comparison.json`。
3. 当前已实现本机校准后的百分比估算，无校准时显示分档。曲线及显示语义见 [百分比方法](BATTERY_PERCENTAGE.md)；精确容量仍未得到验证。
4. 常驻应用宜低频轮询、遇到断开关闭句柄，避免多个调用并发混淆无命令回显的回复。
5. 当前诊断仅对 `04A5:800A` 和接收器固件 `8511` 有实机证据，不能默认推广到其他型号和固件。

当前实现已加入 `device_lock.py`：`query()` 每次访问加锁，`read_live_snapshot()` 将整组查询包在同一锁内，厂商被动监听在整个窗口持锁。锁限定当前 Windows 会话，只协调采用此模块的项目客户端；外部工具和旧脚本不受约束。托盘按每轮完成后 30 秒重试，见 [使用说明](../docs/TRAY.md)。

## 复现

```powershell
# 单次版本查询
# 注意：脚本固定改写 diagnostics/version-query-result.json，复跑前保存旧结果
python diagnostics/query_version.py

# 先核对接收器版本为 8511，再每 2 秒记录电压候选值，2 分钟后退出
python diagnostics/monitor_voltage.py --seconds 120 --out diagnostics/voltage-comparison-new.json
```

命令从项目根目录执行，新记录选择未使用的输出文件名。脚本只使用 Windows HID API；日常读取不需要 USBPcap 或管理员权限。分析更新器所需的 pefile/capstone 安装在 `diagnostics/_analysis_deps`；它们不是当前读取程序的运行依赖，后续托盘也应保持这一边界。
