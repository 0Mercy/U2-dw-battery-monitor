# 项目状态与计划

> 公开副本说明：本文中的“本机”指原开发环境。公开仓库不含官方更新器、提取固件、抓包及原始操作日志；标注“仅本地保留”的证据不随仓库发布。校准与快照为脱敏历史样例，详见 [公开范围](../docs/PUBLICATION.md)。

状态：当前。更新日期：2026-10-08。

## 目标与范围

用户希望日常使用 U2-DW 时能从 Windows 通知区域看到电量，减少查看鼠标指示灯的操作。目标是提供有依据的估算及明确的未知状态。

当前范围是单只 U2-DW、基站无线连接及已分析的固件组合。当前阶段不包含固件升级、设备设置修改、多品牌支持、云同步和精确剩余时长。完整放电曲线与缓存刷新规律仍是待验证假设。

采用**轻量治理**：本地单设备原型，没有服务端、部署流水线或付费服务。硬件协议和电量结论需要同时保留静态分析、实机记录和人工观察，不能只靠文档相互引用确认。

## 当前结构

```text
Start-U2DW.vbs → tray/start.ps1 → WinForms NotifyIcon
  → 独立 Python 子进程 tray/read_battery.py → read_live_snapshot()

battery_percentage.py
  ├─ --snapshot：读取已有原始查询 JSON
  └─ --live：串行调用 query_version.query()
               ├─ hid_probe.py：目标设备枚举、Windows API
               └─ usb_capture.py：复用异步 I/O 封装
  → 校准文件及其证据 → 分档 / 明确标注的百分比估算 → JSON
```

实时路径依次读取接收器版本、鼠标版本、电压、鼠标版本，整个快照持有设备互斥锁。只有查询完成且前后鼠标版本一致才进入解释；异常可能抛出至命令行，托盘读取层将异常转为未知状态，由 UI 定时重试。

| 路径 | 职责 |
|---|---|
| `Start-U2DW.vbs`、`tray/start.ps1` | 隐藏控制台启动、解释器查找及本机 C# 编译 |
| `tray/TrayApp.cs`、`tray/read_battery.py` | 托盘 UI、串行轮询、读取进程与状态转换 |
| `diagnostics/device_lock.py` | 当前 Windows 会话内的设备访问互斥 |
| `diagnostics/battery_percentage.py` | 离线解释、单次实时读取和百分比插值 |

| `diagnostics/monitor_voltage.py` | 1–300 秒有界电压记录，不是完整连接状态监控 |
| `diagnostics/hid_probe.py`、`vendor_listen.py`、`usb_capture.py`、`pcap_summary.py` | 枚举、被动监听和 USB 抓包调查 |
| `diagnostics/inspect_updater.py`、`analyze_battery_thresholds.py` | 更新器静态分析、提取固件的离线执行 |

## 已采纳的关键决策

### 使用已识别的读取命令（2026-09-25）

标准 GET_REPORT 在实机被拒绝，被动监听没有收到电量报告；更新器分析与实机响应确认了厂商查询路径，因此复用当前白名单。详见 [协议证据](../diagnostics/PROTOCOL.md)。换固件、设备组合或发现报告结构变化时重新评估。

### 先提供明确标注的电压估算（2026-09-25）

已识别的接口没有原生容量百分比；固件电量灯阈值与人工满电参考提供了可解释的显示依据。因此当前实现采用分段插值、5 个百分点显示步长，同时保留未知状态。仅显示电压可作为调试输出；继续寻找原生百分比是未来可能的替代路径。模型细节统一见 [百分比方法](../diagnostics/BATTERY_PERCENTAGE.md)。

若自然放电记录显示曲线明显失真、充电造成误导性跳变，或发现原生容量字段，应修订估算模型与展示方式。显示步长不能被宣传为准确度。

### 使用 WinForms 托盘与独立读取进程（2026-09-25）

当前只需要数字图标、悬浮和菜单。本机 Windows PowerShell 可运行 WinForms，因此采用 C# UI 与现有 Python 读取模块，免去安装额外界面库。读取进程具备超时边界，避免 HID 等待阻塞 UI；每轮结束 30 秒后再读取。代价是依赖本机 Python、启动时编译及每次读取创建子进程，未来独立 EXE 打包时重审。

## 当前交付与后续工作

托盘数字、悬浮说明、自动刷新、立即刷新、退出、错误状态及互斥已实现。43 项自动化测试及主要人工/实机操作已通过；真实睡眠唤醒、长期运行及跨环境部署仍未完成，不能等同于成熟发布版。

1. 用户方便时补做真实睡眠唤醒；后续另安排较长时间运行及其他显示缩放条件的验收。
2. 按后续需求增加开机启动、低电量提醒和 EXE 打包。
3. 记录自然放电以评估曲线准确度及缓存行为；不以短时稳定读数替代完整放电证据。

最小有效成果是可持续运行且能区分“估算可用 / 未知”的托盘闭环。验收条目见 [VALIDATION](VALIDATION.md)；百分比完整放电准确度应作为独立结论记录。
